⏺ 4 tests passing. Here's what was scaffolded:

  pelgo/
  ├── __main__.py          # CLI: python -m pelgo --resume foo.pdf --jd "..."
  ├── pdf_extractor.py     # PDF/text → CandidateProfile (pre-agent boundary)
  └── agent/
      ├── schemas.py       # All Pydantic models: CandidateProfile, MatchResult,
      │                    #   AgentState, AgentTrace, ToolCallRecord, ...
      ├── tools.py         # 4 FunctionTools with real signatures + ToolContext
      ├── agent.py         # ADK LlmAgent with system prompt + tool registration
      └── runner.py        # AgentRunner: event-stream trace capture, state
  seeding
  tests/test_smoke.py      # 4 tests: parse, schema round-trip, integration with
   mocked runner

  Key design decisions baked in:

  - PDF extraction is pre-agent — happens at the CLI/API boundary, not a tool
  the LLM decides to call
  - agent_trace is honest — populated by capturing event.get_function_calls() /
  event.get_function_responses() from ADK's run_async event stream, not asserted
   by the LLM
  - AgentState is typed Pydantic, seeded into session.state at run start; tools
  read/write it via ToolContext.state
  - Failure modes are wired — tools catch exceptions and write to tool_errors in
   state; the runner returns _empty_result rather than crashing; the system
  prompt tells the agent how to handle low confidence and timeouts
  - research_skill_resources makes real external calls to Coursera API →
  DuckDuckGo fallback → static stub

  To run with a real API key:
  cp .env.example .env
  # add GOOGLE_API_KEY
  python -m pelgo --resume Pelgo_-_AI_Lead_Assignment.pdf --jd "Senior Python 
  Engineer..."

  workers + DB).
